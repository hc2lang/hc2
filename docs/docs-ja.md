# hc2 プログラミング言語

hc2 は、C のように小さく速く、それでいてメモリ安全であることを目指したプログラミング言語です。

hc2 のポインタは生のアドレスではなく、境界・権限・世代の情報を持ちます。
範囲外アクセスや解放済みメモリの参照は、コンパイラの検査でもガベージコレクタでもなく、実行時のチェックによってエラーになります。
所有権の注釈もライフタイムも書く必要はありません。

Linux と macOS に対応しています。Linux 向け（amd64 / arm64）には静的リンクされた単一の実行ファイルを、
macOS 向け（arm64）にはそのまま実行できる署名済みバイナリを生成します。

```hc2
import "heap";

I32 main() {
    U8* req = heap.alloc(64);
    req[0] = 'G'; req[1] = 'E'; req[2] = 'T';
    "%d-byte request, method %c%c%c\n", req.len, req[0], req[1], req[2];

    U8* view = req;      // ポインターをコピー
    heap.free(req);      // ヘッダへの 1 回の書き込みが全コピーを失効させる
    "%c\n", view[0];     // C なら解放済みメモリを読んで動いてしまう。hc2では実行時エラー
    return 0;
}
```

```
64-byte request, method GET
main.hc2:10: trap: use after free
```

## HelloWorld

```hc2
I32 main() {
    "Hello, world!\n";
    return 0;
}
```

この時点ですでに 2 つ、見慣れないものがあります。print 関数は存在しません。
文字列リテラルが print 文そのもので、カンマの後に `printf` 風の引数を取ります([print文](#print文)参照)。
また、 `main` は `I32` を戻り値として返します。

これを単独のディレクトリに `main.hc2` として保存し、ビルドします:

```sh
mkdir hello && cd hello
# ... main.hc2 を書く ...
hc2 build -o hello .
./hello
```

## コンパイルと実行

hc2ではプログラムはファイルではなくディレクトリです。コンパイラはディレクトリを
受け取り、その中のすべての `.hc2` ファイルを 1 つのパッケージとしてコンパイルし、
import を辿り、1 つの実行ファイルをリンクします:

```
hc2 build [-o out] [-target p] [dir]
                            パッケージツリーをコンパイルし、変更分だけ再ビルドする
hc2 clean [dir]             そのプロジェクトのビルドキャッシュを消す
```

- `-o` を省くと出力名はディレクトリ名になります(`hc2 build hello` は `./hello` を書き出し、`.` は `./a.out` になります)。
- 出力は静的リンクされた１実行ファイルです。
- コンパイル結果をプロジェクトルートの `.hc2cache` にパッケージ単位でキャッシュされます。
- `-target` でクロスコンパイルします。[パッケージとターゲット](#パッケージとターゲット)を参照。

## コメント

```hc2
// 行末までがコメント
I64 x = 1;   // コードの後ろにも書ける
```

コメントは `//` の 1 種類だけです。`/* */` のブロックコメントはありません。

## 関数

```hc2
I32 main() {
    "fib(10) = %d\n", fib(10);
    return 0;
}

I32 fib(I32 n) {
    if n < 2 {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}
```

関数は `戻り値型 名前(型 引数, ...) { 本体 }` です。
前方宣言もプロトタイプもありません。パッケージ内のトップレベル名は、順序に関係なく、そのパッケージの全ファイルからどこでも見えます。

- 引数の個数とすべての型は厳密に検査されます。
- オーバーロードもデフォルト引数もありません。
- 構造体は値渡しできません。ポインタで渡します。
- 構造体を関数の戻り値にできますが、その呼び出しは宣言を直接初期化する形でなければなりません。

## シンボルの可視性

アンダースコアで始まるトップレベル名はパッケージ内プライベートになります。それ以外の名前はすべてエクスポートされます。

```hc2
I64 counter = 0;      // エクスポート: 他のパッケージが pkg.counter を読み書きできる
I64 _step = 1;        // プライベート: このパッケージだけが見える

U0 tick() {           // エクスポート
    counter = counter + _step;
}

U0 _reset() {         // プライベート
    counter = 0;
}
```

このルールは関数、定数、可変グローバル、型、構造体のフィールドに適用されます。

```hc2
struct Pt {
    I64 x;
    I64 y;
    I64 _tag;     // このパッケージのファイルからだけ見える
}
```

## 変数

```hc2
I64 total = 0;
U8 c = 'x';
Bool ok = total == 0;
I64 arr[2] = {10, 20};
```

変数は `型 名前 = 初期値;` の形で宣言します。
初期値は省略できません。ローカル変数、グローバル変数、定数のいずれも
宣言時に必ず初期化されるため、hc2 に未初期化の変数は存在しません。

## 型

### プリミティブ型

| 型  | サイズ(バイト) | 説明 |
|-------|------|-------------|
| `U0`  | 0 | 値なし 0 サイズ |
| `Bool`| 1 | `true` または `false` |
| `I8` `I16` `I32` `I64` | 1 2 4 8 | 符号付き整数 |
| `U8` `U16` `U32` `U64` | 1 2 4 8 | 符号なし整数 |
| `F64` | 8 | IEEE 754 倍精度 [浮動小数点](#浮動小数点)参照 |
| `T*`  | 32 | 型 `T` の値への capability [ポインタ](#ポインタ)参照 |

これで全部です。`enum` はなく(`const I64 NAME = n;` を使います)、
型エイリアスもなく、独立した文字列型もありません(文字列は `U8*`
です)。浮動小数点は F64 の 1 種類だけです。

### 数値

```hc2
I64 a = 42;             // 10進
I64 b = 0xbeef;         // 16進
U8 g = 'G';             // 文字リテラルは整数定数
I64 neg = -5;
```

2進(`0b`)や 8進リテラルはありません(先頭の `0` はただの 10進です)。
桁区切りもリテラル接尾辞もありません。

算術は型の幅でラップします:

```hc2
U8 x = 200;
x = x + 100;         // 300 は U8 では 44 にラップする
"x = %d\n", x;       // x = 44
```

整数除算はゼロ方向に切り捨てます。`%` は剰余です:

```hc2
"div: %d rem: %d\n", 17 / 5, 17 % 5;    // div: 3 rem: 2
```

リテラルのゼロで割るとコンパイルエラー、値がゼロの変数で割ると実行時エラーになります。

シフトは左オペランドの符号に従います。符号付きなら算術シフト、符号なしなら論理シフトです。

```hc2
I64 m = -8;
"sar %d\n", m >> 1;      // sar -4
U64 u = 16;
"shr %d\n", u >> 2;      // shr 4
```

### 浮動小数点

`F64` は IEEE 754 の倍精度です。他の幅はありません。

```hc2
F64 x = 1.5;
F64 k = 1.0e-3;              // 指数も書ける。1e9 も浮動小数
"%f\n", x * 2.0 + 0.25;      // 3.250000
```

- リテラルは小数点の両側に数字が要ります(`1.` や `.5` はパースされません)。指数部は `e` に符号と数字を続けます。
- 使える演算は `+ - * /` と比較だけです。

### 真偽値

`Bool` は整数とは別の型で、値は `true` と `false` だけです。
比較の結果が `Bool` になり、`if` や `for` の条件には `Bool` しか書けません。整数は条件に使えません。

```hc2
Bool ok = 3 > 2;
if ok {
    "ok\n";
}
```

`&&` と `||` は `Bool` 同士を組み合わせ、左が決まれば右は評価しません。
`!` 演算子はないので、否定は `ok == false` のように比較で書きます。
`Bool` は他の型にキャストできません。

### 文字列

文字列は `U8*` です。

```hc2
U8* s = "hello";
"%s has %d bytes\n", s, s.len;      // hello has 5 bytes
"first: %c\n", s[0];                // first: h
U8* head = s[0 : 2];                // スライスはより狭い U8*
"%s\n", head;                       // he
```

文字列は NUL 終端ではなく、長さはポインタが持っています。`.len` はバイト単位の長さです。
文字列リテラルは読み取り専用で、書き込みも `free` も実行時エラーになります。
エスケープは `\n` `\t` `\r` `\0` `\\` `\"` `\'` の 7 つだけです。

文字列型も連結演算子もありません。文字列を組み立てるときは `heap.alloc` したバッファにバイトを書きます。
NUL 終端が必要な場面 (システムコールのパス引数など) には `str.cstr` を使います。

### キャストと型なし定数

暗黙の型変換はありません。

```hc2
U8 a = 1;
I32 b = 2;
I32 c = a + b;    // エラー: mixed-type arithmetic (no implicit conversions; write the `as`)
```

```hc2
"300 as U8 = %d\n", 300 as U8;        // 44
I64 v = -5;
"v as U32 = %d\n", v as U32;          // 4294967291
"wrap %d\n", big as U8 as I64;        // 切り詰めてから再び拡げる
I32* xs = heap.alloc(64) as I32*;     // ポインタから別の型のポインタへ
```

キャストできる組み合わせは 3 つです。

- スカラーからスカラーへ。ただし `Bool` と `U0` はキャストできず、`U64` と `F64` の間も変換できません。
- ポインタから別の型のポインタへ。`heap.alloc` が返す `U8*` を構造体のポインタにするのがこれです。
- ポインタと整数の間は、どちらの向きにも変換できません。アドレスからポインタを作る方法は `sys.from_raw` だけです。

数値リテラルや `sizeof(...)` のような定数は、特定の型を持たない型なし定数です。
代入先や演算相手の型に合わせて型が決まり、その型に収まらない値はコンパイルエラーになります。

## ポインタ

hc2でポインタは生アドレスではありません。32 バイトの capability として扱われます。
アドレスに加えて、実行時にチェックするための境界・権限・世代情報を持ちます。

| ワード | 属性 | 意味 |
|------|-----------|---------|
| 0 | `.addr` | 生のアドレス |
| 1 | `.hdr` | 割り当てのヘッダのアドレス。最下位ビットは書き込み権限 |
| 2 | `.lo`, `.len` | 割り当ての先頭から参照範囲の開始位置までのオフセットと、参照範囲のバイト長 |
| 3 | `.gen` | この capability が期待する世代 |

すべての割り当ては、データの直前に 16 バイトのヘッダ `{長さ, 世代}` を持ちます。
ポインタを介したアクセスは実行時に capability とヘッダの両方と照合されます。
nullポインターのディレファレンス、配列境界外への参照、解放ずみのメモリ参照などは実行時エラーでプログラムを終了します。

5 つの属性（.addr, .hdr, .lo, .len, .gen）はどのポインタからも読め、`I64` 型の数値を返します:

```hc2
U8* p = heap.alloc(64);
"%d %d %d\n", p.len, p.lo, p.gen;     // 64 0 1
```

### スライス

`p[lo : hi]` は、指定した範囲だけを参照する同じ型の新しいポインタを作ります。

```hc2
U8* buf = heap.alloc(64);
I64 n = sys.read(fd, buf);
"read %d: %s", n, buf[0 : n];      // 読んだ分だけを表示する
```

スライスで参照範囲を広げることはできません。新しい範囲は元のポインタの参照範囲と照合されるため、
元のポインタが届かない領域を指すスライスは作れません。また、スライスは元の割り当てを指したままなので、
その割り当てを解放すると、スライス経由のアクセスも実行時エラーになります。

### ポインタ演算

```hc2
Pt* ps = heap.alloc(4 * sizeof(Pt)) as Pt*;
Pt* q = ps + 2;       // 要素単位: 2 * sizeof(Pt) バイト進む
```

ポインタ演算に使えるのは `+` と `-` だけで、ポインタを左辺、整数を右辺に置く形に限られます。
演算結果は元のポインタの境界を引き継ぐため、範囲外を指すポインタを作った時点ではエラーにならず、
そのポインタでアクセスした時点で実行時エラーになります。ポインタ同士の減算や大小比較はできません。

### null

`null` は空のポインタ値です。任意のポインタ型・関数ポインタ型に適応し、
比較は `==` と `!=` だけで、キャストはできません:

```hc2
U0(I64)* g = null;
if g == null { "not set\n"; }
```

## 配列

配列は固定長で、C 風に名前の後ろへブラケットを付けて宣言します。

```hc2
I32 d[4] = {1, 2, 3, 4};
U8* names[3] = {"alpha", "beta", "gamma"};
I64 zeros[8] = {};                       // {} はゼロ埋め
I64 arr[lib.WIDTH] = {};                 // 長さには import した定数も使える
```

- 配列の長さはコンパイル時定数でなければなりません。
- 初期化子の個数は正確に一致しなければなりません。空の初期化式 `{}` は例外です。
- 配列は値ではありません。丸ごとの代入・引数渡し・返却はできません。

```hc2
I64 arr[3] = {1, 2, 3};
I64* p = &arr;               // 配列全体。境界も込み
"%d bytes\n", p.len;         // 24 bytes
```

- 配列参照時のインデックスは実行時に境界検査されます。

### 多次元配列

```hc2
I32 m[2][3] = {{1, 2, 3}, {4, 5, 6}};
m[1][0] = 40;
I64 cube[2][2][2] = {{{1, 2}, {3, 4}}, {{5, 6}, {7, 8}}};
"%d\n", cube[1][0][1];       // 6
```

- 初期化子では各次元が自分の波括弧を持ちます（C 風のフラットな並びは不可)。

## 構造体

```hc2
struct Node {
    I64 kind;
    U8* text;
    Node* next;
}
```

構造体はトップレベルで宣言します。閉じ波括弧の後にセミコロンは付けません。
フィールドは宣言順に配置され、それぞれアラインされ、構造体サイズは 8 の倍数に切り上げられます。

### 構造体リテラル

初期化は位置指定で、全フィールドを埋めるか、ゼロ埋めします:

```hc2
struct Arena {
    U8* buf;
    I64 used;
}

Arena a = {heap.alloc(4096), 0};    // 全フィールドを順に
Arena b = {};                        // すべてゼロ
```

### プライベートフィールド

`_` で始まる名前のフィールドは定義パッケージ内プライベートです [シンボルの可視性](#シンボルの可視性)を参照。

## 共用体

共用体はメンバをオフセット 0 に重ねます。サイズは最大メンバを 8 の倍数に切り上げたものです:

```hc2
struct TimeDate {
    U32 time;
    I32 date;
}

union Date {
    I64 i64;
    TimeDate td;
}

I32 main() {
    Date d = {};                     // 共用体にリテラル形式はない。{} のみ
    d.i64 = 0x11223344AABBCCDD;
    "time %x date %x\n", d.td.time as I64, d.td.date as I64;
    // time aabbccdd date 11223344   (リトルエンディアン)
    return 0;
}
```

共用体は、同じビット列を別の数値型として読み替えるためのものです。
メンバに置けるのはスカラーと、すべてのフィールドがスカラーである構造体に限られます。
capability や関数ポインタは、共用体を経由して任意の数値を capability に変換できてしまうのを防ぐため、メンバにすることはできません。

`unsafe union` は、この制限だけを外した共用体です。ただし、capability メンバの読み取りはすべて `unsafe { }` ブロックの中で行う必要があります。

## 可変長引数関数

関数の最後の引数には、任意個のスカラー引数をまとめて受け取ることができます。

```hc2
I64 sum(I64... xs) {
    I64 total = 0;
    for I64 i = 0; i < xs.len / 8; i++ {    // .len は byte サイズ。
        total = total + xs[i];
    }
    return total;
}

I32 main() {
    "sum %d\n", sum(1, 2, 3, 4, 5);   // sum 15
    "sum %d\n", sum();                // sum 0
    return 0;
}
```

関数の中では、可変長引数は通常のポインタとして扱われます（この例では `I64*`）。
添字でのアクセス、スライス、`.len` の読み出しがそのまま使えます。
実際に渡された引数の数を超えてアクセスすると、他のポインタと同様に`out of bounds` の実行時エラーになります。
可変長引数を読み過ぎても、スタック上の他のデータを覗き見ることはできません。

## 関数ポインタ

関数の型はシグネチャに `*` を付けたものです:

```hc2
I32 add(I32 a, I32 b) { return a + b; }
I32 mul(I32 a, I32 b) { return a * b; }

struct OpEnt {
    U8* name;
    I32(I32, I32)* f;
}

const OpEnt OPS[2] = {
    {"add", &add},
    {"mul", &mul},
};

I32 main() {
    I32(I32, I32)* f = &add;      // & が値を鋳造する
    "direct %d\n", f(2, 3);       // 関数のように呼ぶ
    f = &mul;
    for I64 i = 0; i < 2; i++ {
        "%s %d\n", OPS[i].name, OPS[i].f(4, 5);
    }
    return 0;
}
```

## パッケージのimport

パッケージは、`.hc2` ファイルを集めたディレクトリです。ディレクトリ内のすべての
ファイルは 1 つのスコープを共有します。サブディレクトリは別のパッケージになります。

たとえば、次のようなプロジェクトを考えます。

```
myapp/
├── main.hc2
└── geom/ # パッケージ "geom"
├──── point.hc2 # Pt, make
└──── vec.hc2 # dot
```

`main.hc2` からは、ディレクトリ名を引用符で囲んで import し、
ディレクトリ名を修飾子として使います。

```hc2
import "geom";

I32 main() {
    geom.Pt a = geom.make(3, 4);
    "dot = %d\n", geom.dot(&a, &a);
    return 0;
}
```

## 文と式

### print文

文字列リテラルで始まる文は print として扱われます。

```hc2
"plain text\n";
"%s has %d bytes\n", name, name.len;
"hex: %x  char: %c  100%%\n", 48879, 104;
```

|  | 引数 | 出力 |
|------|----------|--------|
| `%d` | 任意の整数 | `I64` に拡げた後の符号付き 10進(符号なしはゼロ拡張: `-5 as U32` は `4294967291` と印字) |
| `%x` | 任意の整数 | 小文字 16進。`0x` なし、パディングなし |
| `%c` | 任意の整数 | 下位バイトを 1 文字として |
| `%s` | `U8*` | `.len` バイト全部 |
| `%f` | `F64` | 符号 + 整数部 + 小数 6 桁。特別値は `inf` `-inf` `nan`(NaN の符号は印字しない)。絶対値が 2^63 以上は `d.dddddde+NN` の近似指数表記 |

print の出力はすべて stdout に行きます。

### if

```hc2
if mask > 100 {
    "big %x\n", mask;
} else if mask == 3 {
    "three\n";
} else {
    "small %d\n", mask;
}
```

条件に丸括弧は付けません。波括弧は必須です。条件は厳密に `Bool` です。

### forループ

ループは `for` だけで、3 つの形があります。

```hc2
for I64 i = 0; i < 10; i++ {       // カウント形
    "%d", i;
}

for n > 1 {                        // 条件のみ
    n = n / 2;
}

for true {                         // 無限ループ
    if done() { break; }
}
```

```hc2
for I32 i = 0; i < 10; i++ {
    if i == 3 { continue; }
    if i == 6 { break; }
    "%d", i;
}
// 01245 と印字される
```

### switch

`switch` は常にジャンプテーブルにコンパイルされます。

```hc2
U8* classify(I64 c) {
    switch c {
        case '0' ... '9':
            return "digit";
        case 'a' ... 'z', 'A' ... 'Z':     // 範囲とカンマ列は組み合わせられる
            return "letter";
        case ' ', '\t', '\n':
            return "space";
        default:
            return "other";
    }
    return "unreachable";
}
```

- 対象は整数でなければならず、各 case 値はその型の定数です。
- 範囲は 3 つのドットで、小さい方から大きい方へ書きます。caseの重複・重なりはコンパイルエラーです。
- `default` は最大 1 つで、最後の節でなければなりません。

暗黙のフォールスルーはありません。

```hc2
switch x {
    case 1:
        n = n + 1;
        fallthrough;
    case 2:
        n = n + 10;
    case 3:
        n = n + 100;         // x == 3 のときだけ到達する
}
```

```hc2
for I64 i = 0; i < 10; i++ {
    switch i {
        case 3:
            continue;            // ループの continue
        case 7:
            break;               // ループの break
        case 0 ... 2, 4 ... 6:
            sum = sum + i;
    }
    sum = sum + 100;
}
```

### defer

`defer` はブロックの終わりまで先送りし、溜まったものを逆順に実行します。

```hc2
U0 note(I32 n) { "note %d\n", n; }

I32 main() {
    defer note(1);
    defer note(2);
    "body\n";
    return 0;
}
```

```
body
note 2
note 1
```

```hc2
U8* buf = heap.alloc(4096);
defer heap.free(buf);
```

### unsafeブロック

`unsafe` の中でだけ許される操作は 2 つあります。
- `asm` ブロックからメモリを直接読み書き。
- `unsafe union` を通して生のワードを capability として取り出すこと。

```hc2
unsafe {
    asm {
        MOV RAX, h
        MOV [RAX], RCX       // メモリに直接書く
    }
    return c.p;              // 生のワードを capability として取り出す
}
```

## メモリ管理

hc2 にはガベージコレクタも借用チェッカもありません。メモリは `heap` パッケージを使って明示的に確保・解放します。
解放後のポインタは、使用時にすべて実行時エラーとして検出されるため、use-after-free や二重解放が黙って通ることはありません。

### heapパッケージ

```hc2
import "heap";
```

| 関数 | 動作 |
|----------|----------|
| `U8* alloc(I64 n)` | `n` バイトを確保する。書き込み可、16 バイトアライン |
| `U0 free(U8* p)` | 割り当てを解放し、以後のアクセスを実行時エラーにする |
| `I64 mark()` | 現在の割り当て位置を記録する |
| `U0 release(I64 m)` | `mark` 以降の割り当てをまとめて解放する |

`alloc` が返すメモリは常にゼロ埋めされています。
メモリを使い切ると実行時エラーで終了します。

### freeと失効

`heap.free` は、解放したメモリを再利用に回す前に、その割り当てを失効させます。
各割り当てはヘッダに世代を持ち、各ポインタは自分が期待する世代を持っています。
`free` はヘッダの世代を進めるため、そのメモリを指していたポインタはコピーも含めてすべて食い違い、次に使われた時点で実行時エラーになります。

```hc2
U8* a = heap.alloc(16);
U8* b = a;               // ポインタは自由にコピーしてよい
heap.free(a);
U8 x = b[0];             // 実行時エラー: use after free
```

`free` に渡せるのは `heap.alloc` が返したポインタそのものだけです。
次の場合は実行時エラーになります。

| 誤り | エラー |
|---------|------|
| リテラル、`&ローカル`、グローバルテーブルの解放 | `heap: trap: free of immortal` |
| スライス（`p[8:16]`）や内部ポインタ（`p + 1`）の解放 | `heap: trap: free: not the allocation base` |
| 二重解放 | `heap: trap: double free` |

### markとreleaseによるアリーナ

一時的な割り当てをまとめて捨てたい場合は、`mark` と `release` を使います。
`mark` で位置を記録し、`release` でそこまで巻き戻すと、その間に確保したメモリがすべて解放されます。

```hc2
I64 m = heap.mark();
for I64 i = 0; i < 4000; i++ {
    U8* p = heap.alloc(1 << 16);
    // ... p を使う ...
    heap.release(m);         // ここまでの割り当てをまとめて解放する
}
```

### sys.from_rawによるcapabilityの鋳造

`sys.from_raw(I64 addr, I64 len)` は、生のアドレスから検査付きのポインタを作ります。
`addr` の直前にヘッダを書き込み、`[addr, addr + len)` を参照する書き込み可の capability を返します。

```hc2
import "sys";

I64 base = sys.mmap(65536);              // 生のメモリ: ただの I64
U8* p = sys.from_raw(base + 32, n);      // 検査付きポインタになる
```

`from_raw` はコンパイラの組み込みではなく、`sys` パッケージに hc2 で書かれた通常の関数です。
内部では `unsafe` ブロックの中で `asm` によるストアと `unsafe union` を使っています（[unsafe ブロック](#unsafeブロック) を参照）。

`sys.mmap` と `from_raw` を組み合わせれば、独自のアロケータを作ることもできます。
そこから得たポインタも `heap.alloc` のものと同じように境界検査され、`.len` を
持ち、`heap.free` で失効させることができます。

## 実行時エラー（トラップ）

実行時に走るcapabilityチェックに違反した操作は、エラーとして検出されます。
エラーが起きると、プログラムは stderr にメッセージを出力し、終了コード 134 で即座に終了します。
例外のような回復手段やハンドラはなく、巻き戻しも行われません。壊れた状態で処理を続けるより、その場で止まることを選ぶ設計です。

| エラー | 発生する状況 |
|------|-------------|
| `out of bounds` | ポインタの参照範囲を超えた添字・スライス・アクセス |
| `use after free` | 解放済みのメモリへのアクセス |
| `write to read-only` | 読み取り専用のポインタ（文字列リテラルなど）への書き込み |
| `division by zero` | ゼロによる `/` または `%` |
| `out of memory` | ヒープを使い切った |
| `free: not the allocation base` | `alloc` が返したポインタ以外の `free`、または不正な `release` |
| `double free` | 解放済みのメモリを再度 `free` |
| `free of immortal` | リテラル・スタック・グローバルを指すポインタの `free` |
| `call through null` | null 関数ポインタの呼び出し |
| `not a function of this type` | 関数ポインタの型が呼び出し側と一致しない |
| `print of null` | null ポインタを `%s` で出力 |

## ランタイム

### コマンドライン引数

```hc2
import "rt";

I32 main() {
    "program: %s, %d args\n", rt.arg(0), rt.argc();
    for I64 i = 1; i < rt.argc(); i++ {
        "  %s\n", rt.arg(i);
    }
    return 0;
}
```

`rt.argc()` はプログラム名を含めた個数、`rt.arg(i)` は `i` 番目の引数を
`U8*` として返します(長さに終端 NUL は含みません)。範囲外の添字は
`rt: trap: out of bounds` でトラップします。

## インラインアセンブリ

`asm` ブロックには機械語の命令を 1 行 1 命令で書きます。hc2 のローカル変数は名前のままオペランドに使えます。

```hc2
I32 main() {
    I32 a = 10;
    asm {
        MOV EAX, a       // hc2 の変数を読む
        ADD EAX, 5
        MOV a, EAX       // 書き戻す
    }
    "a: %d\n", a;        // a: 15
    return 0;
}
```

メモリを直接読み書きする命令は[unsafe ブロック](#unsafeブロック)の中でだけ書けます。
スタックフレームはコンパイラの所有物で、`asm` からは触れません。

使える命令とレジスタはターゲットごとの小さなメニューに限られ、メニューにない命令はコンパイルエラーになります。
x86-64 は基本的な演算・分岐・システムコール命令、arm64 は `sys` を書くのに足りる最小限です。

## パッケージとターゲット

ターゲットは os/arch のペアです:
- `linux/amd64`
- `linux/arm64`
- `macos/arm64`

どのファイルがどのターゲットでコンパイルされるかは、ファイル名が決めます。末尾の `_` セグメントを右から読みます:

| ファイル名 | コンパイルされるターゲット |
|-----------|--------------|
| `rt.hc2` | すべて |
| `rt_linux.hc2` | linux の両ペア |
| `rt_arm64.hc2` | arm64 の両ペア |
| `rt_linux_arm64.hc2` | そのペアのみ |

このルールはすべてのパッケージに適用されます。ファイル内の条件付きコンパイルは存在しません。

クロスコンパイルはフラグ 1 つです:

```sh
hc2 build -o server -target linux/arm64 .
```
